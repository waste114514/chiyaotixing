# 吃药提醒 · M3 备份测试说明

> 目标：验证 0.4.0-m3 的「导出备份 / 从备份恢复」。
>
> 备份是一个 JSON 文件，通过系统文件选择器保存和读取；不申请存储权限，不联网。

| 项 | 值 |

## 2. 导出

1. 打开 App → 设置 → 数据 → 「导出备份」。
2. 系统会弹出保存位置（文件、下载、微信收藏等由系统提供）。
3. 选择位置并确认。
4. 预期：提示「备份已保存」。
5. 找到文件，文件名类似 `吃药提醒备份-2026-10-24.json`。

用文本编辑器打开应该能看到开头是：

```json
{"app":"yaodian","format":1,"exportedAt":"...","versionName":"0.4.0-m3","plan":{...},"state":{...},"events":[...]}
```

> 文件是明文 JSON，包含药名和服药记录。请放在自己手机或自己的云盘里，不要发到公开群。

## 3. 恢复

1. 设置 → 数据 → 「从备份恢复」。
2. 在文件选择器里选刚才导出的 JSON。
3. 预期：App 内弹出一张「恢复备份」页面，显示：
   - 导出时间
   - 药品：N 种 · M 顿
   - 历史记录：X 天 · Y 条
4. 点「确认恢复」→ 提示「已恢复备份」，自动回到今天页。
5. 点「取消」→ 什么都不改。

## 4. 重点测试

| # | 场景 | 预期 |
|---|---|---|
| 1 | 导出后添加一条药、确认几项，再恢复 | 药品和历史回到导出时的状态，新加的药消失 |
| 2 | 恢复后看当前阶段 | 阶段和导出时一致；通知、锁屏卡片同步刷新 |
| 3 | 恢复后看记录页 | 历史天数、每天状态和导出前一致 |
| 4 | 选一张照片或其他 JSON | 提示「这不是吃药提醒的备份文件」或「备份格式不支持」，数据不变 |
| 5 | 恢复预览点取消 | 数据不变 |
| 6 | 恢复完再确认一项 | 正常推进，撤销也可用 |
| 7 | 覆盖安装后再恢复 | 同样可用，数据不依赖安装过程 |

## 5. 不包含的内容

- 系统权限：通知权限、无障碍（锁屏卡片）开关不会被备份，换机后要重新开。
- 通知设置、App 版本、手机相关设置不在备份里。
- 备份不合并：恢复是整体覆盖，不能只导入某一天的记录。

## 6. 已知限制

- 文件是明文 JSON，没有加密。
- 备份上限：20 MB、10 万条事件、200 种药、6 顿；超出会提示。
- 恢复过程中如果 App 被系统杀掉，需要重新选一次文件。
- 恢复会重写历史文件；当前正在显示的通知会按恢复后的状态重发。

## 7. 反馈

1. 保存位置选择器是否正常弹出，能不能存到文件管理/下载。
2. 导出的文件能不能在文件管理里看到、大小是否合理。
3. 恢复预览的三项数字是否和实际相符。
4. 恢复后药品、今天阶段、记录页是否正确。
5. 错误文件的提示是否清楚。
6. 异常截图或 `adb logcat -s MedApp`。
